# Replatforming Verification

The standalone Next.js administrator dashboard was launched from `admin-dashboard/` and inspected at desktop size. The current offline-ready mode rendered the Coursewise sidebar, Overview, Students, Announcements, Lessons, Quizzes, Attendance, Settings navigation, the role-aware administrator identity card, the Firebase configuration indicator, and management overview cards.

The production validation command `NODE_ENV=production pnpm build && pnpm lint` completed successfully in `admin-dashboard/`. The root Vitest suite completed successfully with 14 tests, including dedicated Next.js offline record tests that cover create, edit, delete, isolation by management module, and the exact `Excused` attendance status, plus a trusted Firebase quiz-score test. The administrator application now includes section-specific forms for students, announcements, lessons, quizzes, and attendance; a dedicated quiz-question and result-review panel; a Firebase-ready role gate; persistence contracts; question/attempt adapters; and a callable-function source that recalculates quiz scores before storing an attempt. Actual Firestore reads and writes remain an account-specific deployment step because no Firebase project credentials were supplied.

The local environment does not contain the Flutter or Dart SDK, so the Flutter source scaffold could not be compiled or run here. Its source structure, Firebase initialization fallback, Riverpod providers, GoRouter routes, and Firestore integration boundaries have been reviewed in source; platform generation and `flutter analyze` remain the final machine-specific checks.

The Firebase CLI was also run with a demo project ID. It started the Firestore Emulator successfully using the repository `firebase.json`, `firestore.rules`, and index configuration, then completed and shut down cleanly. This verifies that the local Firestore configuration is consumable without any account credentials. Authenticated role-based reads and writes still require a real Firebase project or a fuller emulator test harness with authenticated identities.
